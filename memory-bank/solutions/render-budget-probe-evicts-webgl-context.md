Symptom: nebula scene rendered completely blank/white after wiring in `@triforge/render-budget-core`'s device profiler.

**Root cause:** The hardware profiler measures the browser's real WebGL context ceiling by deliberately creating scratch contexts until the browser evicts the oldest one. It was running from inside `CarouselPlanets.init()`, reached after `LandingEngine`'s nebula renderer already existed — so the nebula's real context became collateral damage. Confirmed via instrumenting `HTMLCanvasElement.prototype.getContext` in headless Chromium.
**Fix (two steps):** (1) Split hardware profiling (`resolveHardwareCeiling()`, network-independent) from full plan resolution (`resolveFullPlan()`, adds network profiling) in `src/scripts/core/landing/RenderBudget.ts`; `LandingOrchestrator.init()` awaits the hardware ceiling as its literal first action, before constructing `LandingEngine`. (2) `resolveFullPlan()` composes the plan manually from the package's individually-exported pieces instead of calling `initRenderBudget()` a second time (which always re-runs its own internal probe) — eliminated a residual momentary Context-Lost-then-Restored event.
**How to spot again:** Any "renderer randomly shows blank/white" bug after adding a new library that touches WebGL — check console for `Too many active WebGL contexts` before assuming it's a shader/material bug. Any hardware-probing code must run before any real renderer is constructed, every time — not just once at initial wiring.
